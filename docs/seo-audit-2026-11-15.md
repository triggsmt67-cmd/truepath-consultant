# True Path Digital SEO audit and content recommendations

Reviewed November 15, 2026. Trevor approved the public technical release and the scoped WordPress cleanup; both are now live and verified. Content rewrites, consolidation, deletion, and unrelated settings remain separate work. Original audit observations below describe the site before these releases; completion details are in Deployment status and the README checklist.

**Step 2 correction and completion:** The original backend-indexability finding missed an existing lowercase `x-robots-tag: noindex, nofollow` HTTP header. That header was present in the original capture and overrides the conflicting HTML `index, follow` directive for Google. The backend homepage should not have been described as indexable. Authenticated inspection identified the custom `.htaccess` block supplying the noindex header and catch-all `/blog/` redirect. The [approved cleanup and release record](wordpress-cleanup-proposal/README.md) now documents the live replacement, API preservation, rollback, and passing verification.

The public site's important pages are accessible. The main technical problems are a poorly linked worksheet, article links removed during rendering, and an exposed WordPress frontend with broken archive and sitemap redirects. Content quality also needs attention: several articles make unsupported claims, one reverses a formula, and two AI-search articles substantially overlap. These findings do not establish why Google excluded any particular page.

## Problems confirmed

### Public website

- The preferred origin is `https://truepath406.com`. Its live sitemap contains 25 pages: six static pages and 19 articles. Every entry returned HTTP 200, a self-referencing canonical, and index/follow metadata. Main content is present in server HTML, including the service pages and articles. No important public page was found blocked by robots.txt or an HTTP noindex header.
- `/checkup` is a useful public worksheet with its own canonical, but it was missing from the sitemap and had no incoming anchor links in the inspected public pages. Its Twitter metadata inherited homepage copy. Its Open Graph object replaced the root object's image fields without supplying a worksheet image.
- For articles in the configured internal-link list, the renderer removed **all existing public-site anchors**, then attempted to insert selected links. This discarded editorial links. For example, the CMS version of `/insights/thin-service-pages-look-generic` linked to the AI-search article, but its live public version did not. Domain normalization also left legacy service links dependent on redirects in posts outside this list.
- Public redirects generally work. Non-www `/blog/article` goes to `/insights/article` in one permanent 308 redirect. A trailing slash adds another hop; `www` usually adds one more. The supplied redirect URLs reach relevant 200 destinations without loops. These are healthy exclusions, with some avoidable historical hops, rather than evidence of broken indexing.
- `/privacy-policy/` redirects to `/privacy-policy`, which returns 404. No link to it was found in inspected public anchors. There is no privacy-policy page in this repository. Review what notice the website's forms and providers need; do not invent a policy or redirect it to an unrelated page. That review is separate from deciding whether Google should index it.

### WordPress backend

- `https://admin.truepath406.com/` returns 200 and a canonical pointing to itself. Its HTML says `index, follow`, but its HTTP header says `noindex, nofollow`; the restrictive HTTP rule means this is not evidence of an indexable homepage. Its template promotes a flower-delivery business called Fleurs, leaving irrelevant public content and archive discovery on the backend.
- The backend homepage exposes links to date/category archives, including all seven reported archive URLs. No links to those archives were found on inspected Next.js public pages. This is a current source of unnecessary crawl discovery.
- Those seven archives now return a 301 into `/blog/...`, then public redirects ultimately reach nonexistent `/insights/...` paths and return 404. The final 404 is appropriate; the intermediate invented article paths are not useful replacements.
- Admin robots.txt permits crawling and advertises its Yoast sitemap index. The index returns 200, but all five child sitemaps (`post-sitemap.xml`, `page-sitemap.xml`, `category-sitemap.xml`, `post_tag-sitemap.xml`, `author-sitemap.xml`) redirect into public article paths and end at 404. This is consistent with the reported zero discovered pages; it does not establish the exact date Google encountered that condition.
- The admin feed also redirects to `/insights/feed` and ends at 404.
- The public GraphQL endpoint supplies all 19 published articles, dates, excerpts, images, content, and optional overview fields. Local production generation works through the same endpoint. No API access was disabled or authentication changed.
